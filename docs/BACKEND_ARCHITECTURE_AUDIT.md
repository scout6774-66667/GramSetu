# GramSetu AI — Backend Architecture Audit

**Audit Date**: 2026-11-22  
**Auditor**: Principal Data Engineer, Senior Backend Architect & Data Quality Auditor  
**Repository**: GramSetu AI (Rural Food Supply Chain Resilience & Recovery System)  
**Execution Environment**: Python 3.11.9, FastAPI 0.141.1, Pydantic 2.13.5, Windows 11 Enterprise  
**Storage Architecture**: Zero-Database Engine — In-Memory State (`InMemoryStore`), Single-Process OS File Lock (`ProcessWriterLock`), Copy-on-Write `RLock` Transactions, Atomic Disk Snapshotting (`write + fsync + replace`).

---

## 1. Executive Summary
This audit provides an exhaustive, code-verified inspection of the GramSetu AI backend. Every endpoint, service function, data schema, storage collection, algorithmic model, and data dependency has been traced directly from source code (`gramsetu/main.py`, `gramsetu/core.py`, `gramsetu/schemas.py`, `gramsetu/store.py`, `gramsetu/algorithms.py`, and `gramsetu/services/*.py`).

The application implements a modular monolithic architecture containing **9 domain modules** and **3 cross-cutting infrastructure services**, exposing **56 FastAPI routes** backed by **49 Pydantic v2 schemas** and **15 in-memory store collections**. Currently, the repository contains **zero external reference datasets, zero commodity catalogs, zero geographic GIS layers, and zero authentic market price tables**. All existing test runs rely on hardcoded test fixtures (`DEV_ACTORS`, `CROP_SHELF_LIFE_DAYS`, `BUYER_DISTANCE_KM`, and an 8-node road network).

## 3. Structural Findings & Inconsistencies

1. **Complete Absence of External Reference Data**:
   - The codebase has zero external master tables. All commodities, grades, varieties, and locations are arbitrary strings without normalization or validation against canonical standards.
   - For example, a user can submit `crop: "xyz123"`, `variety: "fake"`, `grade: "AAA+"` and the backend will process it without error.
2. **Hardcoded Geographic & Route Topology**:
   - `gramsetu/algorithms.py` contains 8 hardcoded nodes and 12 directed edges representing a toy network in Western Maharashtra. Querying any real-world coordinates outside these 8 nodes results in `ROUTE_UNVERIFIED`.
   - `gramsetu/services/recovery.py` contains hardcoded distance estimates: `BUYER_DISTANCE_KM = {"buyer-local": 10.0, "buyer-bigbasket": 45.0, "buyer-reliance": 120.0}`.
3. **Missing Market Intelligence Engine**:
   - While the architecture document (`docs/ARCHITECTURE.md`) prominently specifies a "Market Intelligence" engine for Agmarknet price and arrivals analysis, **no service, schema, or route currently exists** for it in `gramsetu/`.
4. **Static Shelf-Life and Spoilage Rules**:
   - `gramsetu/services/risk.py` uses a hardcoded dictionary (`CROP_SHELF_LIFE_DAYS`) with 9 crops. If a crop is not listed, it defaults to 7 days regardless of commodity physiology or storage conditions.
5. **Simulated Actor Fixtures**:
   - In development/testing, authentication is tied to a static Python dictionary `DEV_ACTORS` in `gramsetu/core.py`.
   - In production (`ENVIRONMENT=production`), JWT authentication is implemented and verified, but there is no database or external directory for user registration.
