# GramSetu AI — Hardening Defect Register

| Defect ID | Severity | Root Cause Summary | Impact | Repair & Mitigation | Verification Test | Status |
|---|---|---|---|---|---|---|
| **DEF-01** | **P0** | Silent 8-candidate truncation (`[:8]`) in `generate_recovery_plan` | Left higher-paying buyers (e.g. 85 paise/g) unexamined, selecting inferior sub-optimal buyers (30 paise/g) causing massive farmer revenue loss | Rebuilt `optimize_recovery_allocation` to evaluate all candidate requirements up to safety limit (200), compute exact net returns (price minus transport), apply multi-criteria deterministic tie-breaking, and return honest optimality flags (`OPTIMAL_PROVEN`, `FEASIBLE_NOT_PROVEN_OPTIMAL`, `NO_POSITIVE_NET_OPTION`). | `tests/hardening/test_recovery_gt8_oracle.py` | **RESOLVED** |
| **DEF-02** | **P0** | In-process `threading.RLock` did not protect against multi-process concurrency | Two Uvicorn worker processes pointing at `data/state.json` would concurrently overwrite the snapshot, corrupting physical inventory and event ledgers | Implemented `ProcessWriterLock` using OS-level exclusive file locking (`msvcrt.locking(LK_NBLCK)` with `FILE_SHARE_READ \| FILE_SHARE_WRITE \| FILE_SHARE_DELETE` on Windows, `fcntl.flock(LOCK_EX \| LOCK_NB)` on POSIX). Second writer fails fast with `ProcessLockError(CONCURRENT_WRITER_COLLISION)`. | `tests/hardening/test_process_writer_lock.py` | **RESOLVED** |
| **DEF-03** | **P1** | Security vulnerability: `X-Dev-Actor` header accepted indiscriminately in production | Any external client could spoof arbitrary roles (e.g. `X-Dev-Actor: fpo-admin-alpha` or `system-worker`) and manipulate data without authentication | Implemented pluggable `IdentityAdapter` framework with `DevIdentityAdapter` and `JwtIdentityAdapter`. Rejects `X-Dev-Actor` in production with 401; validates JWT Bearer tokens with pinned cryptographic algorithms (`HS256`, `RS256`), rejects `alg=none`, validates `iss`, `aud`, `exp`, and maps claims to `DevActor`. | `tests/hardening/test_auth_negative.py` | **RESOLVED** |
| **DEF-04** | **P1** | Logistics feasibility relied solely on Haversine chord distance and fixed 40 km/h speed | Ignored real road network connectivity, bridge weight limits, river barriers, and monsoon washouts, leading to unexecutable dispatch schedules | Implemented `OfflineRoadGraphProvider` with Dijkstra shortest-path / lowest-duration routing, explicit bridge/road closure detection, vehicle payload weight limits, and honest route statuses (`ROUTE_VERIFIED`, `ROUTE_UNVERIFIED`, `NO_FEASIBLE_ROUTE`). | `tests/hardening/test_road_graph_routing.py` | **RESOLVED** |
| **DEF-05** | **P1** | Unverifiable payment claims and weighbridge readings without cryptographic provenance | Vulnerable to duplicate webhook replays, tampered payment amounts, and uncalibrated scale readings falsely marked as confirmed | Implemented `ProvenanceEvidenceRecord` and `EvidenceManager`. Every financial transaction and physical scale reading computes SHA-256 canonical payload digest; enforces honest lifecycle (`REPORTED` -> `OPERATOR_CONFIRMED` -> `EXTERNALLY_VERIFIED`); prevents duplicate references with 409 Conflict. | `tests/hardening/test_evidence_integrity.py` | **RESOLVED** |
| **DEF-06** | **P2** | In-process cold restart simulations in tests failed due to lingering file handles | Simulating cold restart within single-process pytest suite raised `PermissionError` when starting a second coordinator before closing the first | Added graceful `.close()` method to `TransactionCoordinator` and updated lifecycle in simulated restart tests. | `tests/test_durable_events.py`, `tests/test_final_acceptance.py` | **RESOLVED** |
